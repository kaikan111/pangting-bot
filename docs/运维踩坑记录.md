## 二、技术侧：当时暴露的问题

### 2.1 记忆与花名册 —— 全场讨论最久的一条

**原话**：
- 「她记忆咋样」→「无」
- 「看设定，上下文越长肯定越吃 Token，陌生人不记住，特意标注的人两小时，我是永久」
- 「12 小时的上下文记忆应该够吧」
- 「你除了认识我还认识谁？」→ 她答不出任何人
- 「我猜他跟你们的对话里面不会出现泥鳅两个字」
- 「1. 不会玩儿梗 2. 没有花名册，除了我谁也记不住，但是他知道自己在跟别人聊天」
- 「他有记忆，我觉得只是没有分类」
- 「他的记忆太散了」

**当时的判断（你说对了的）**：「没有花名册 = 记忆丢失，现在给名字算是对号入座」。
**后来的实际根因**：不是记性差，是**群过滤 `return` 在写历史之前**，别人的话一条都没进过她的上下文。
**已落地的解**：群旁听（`recordEavesdrop`）+ 花名册（`get_group_member_list`）+ 人物档案（`profile`）+ 自动记忆提取（`facts`）。

> 模板教训：**「她记不住」要先分清是「没收到」还是「收到了没记住」**，这两种改法完全不同。

### 2.2 识图

**原话**：
- 「小禾 你能识图吗」
- 「不是，为什么他能看你图片？」
- 「都可以吧，可能格式不同，因为我发的直接是相册里面的图片，**这也是漏掉的地方**」
- 「你能看到我发的图片吗？」

**你当时的直觉是对的**：相册发出来的图确实漏。
**实际根因**：只解析了 `text` / `at` / `image` / `mface` 四种段，**`forward`（合并转发）、`json`（收藏卡片）、`face`（QQ 小黄脸）整段被丢掉**。
**已落地的解**：`collectSegs` 递归解析 + `expandForward` 调 `get_forward_msg` 展开 + `FACE_MAP` 把表情 id 翻成 emoji。
**顺带修的暗雷**：`VISION_MODEL` 会劫持所有纯文字调用（记忆/档案/摘要），已改成只有真带图才切视觉模型。

> 模板教训：**「图看不见」不代表模型瞎，先查段解析有没有吃进去**。

### 2.3 DeepSeek 认知

**原话**：
- 「不对，设定里面他没把自己认为是 DS」
- 「没有认知呀，光靠设定可能不够」
- 「DS 和你啥关系」
- 「你认识 deep seek 吗？」

**已落地的解**：人设里加了【聊 AI 的时候】段 —— 她知道底下跑的是 DeepSeek，但不说「我是 AI 助手」，聊别家 AI 用调侃语气。

> 模板教训：**「她是谁」和「她是什么引擎」要分开写**，混在一起她会开始念参数字。

### 2.4 安全墙与设定的冲突

**原话**：
- 「不能改设定，我加了屏蔽词的」
- 「会和功能冲突然后报错」
- 「这是我留下的防止破坏设定的墙」
- 「太敏感」（有人说 `【PERSONA_LOAD]` 就被拦了）

**当时的问题**：墙误杀得厉害 —— 正则里带着「说」，导致「跟我说话」这种正常句子也被当越狱话术拦。
**已落地的解**：22 句正常话探针，只留 3 句真该拦的；出口墙只拦政治/色情/违法三类。

> 模板教训：**安全墙的正则要拿「正常聊天语料」回去跑一遍**，不是拿攻击语料跑通就算数。

### 2.5 文字 + 图一起发会分两回

**原话**：「这个短时间内文字和图一起发他是分开回复，这也得修，没有融合」

**已落地的解**：连发合并（`debounceMs`）+ 去重 + 多条编号排给模型（①②③）。

## 三、口语化侧：当时最尖锐的批评

> 这一段是全群最有价值的部分，几乎每句都是需求。

| 原话 | 说的是什么 | 翻译成技术需求 |
|---|---|---|
| 「我感觉有点应答式了」 | 一味顺着答，像客服 | 要有反问、要有自己的立场 |
| 「性格写的太死了，而且好像缺了什么一样，很奇怪」 | 每句都同一副脸 | 招式轮盘 + 概率调制 |
| 「就算询问也换个调调，还是太死板了」 | 「先说明再询问」句式固定 | 禁止固定句式，随机打法 |
| 「好直白呀，应该让他傲娇一点才对」 | 缺情绪层次 | 情绪状态机（生闷气） |
| 「**真的有股原版 DS 的语气**」 | 一听就是模型 | 这是最要命的一条 |
| 「**正常人谁这么说话**」 | — | 同上 |
| 「好像只会挨个回复，然后一次性说完，**没有自己的思维**」 | 机械串行 | 分段发 + 随机延迟 |
| 「而且只会挨个回复」 | 同上 | 同上 |
| 「你是说要分段式口语化？」 | 你当时的判断 | 拟人打字延迟 + 分段 |
| 「但是一段段回如果是群里太多消息会任务滞后，然后上下文全是不规则错开」 | 你顾虑的代价 | 所以要合并 + 编号，不是硬拆 |
| 「那正确的模板是啥样的」 | 求样例 | 人设里要配**台词样例**不是形容词 |
| 「那要是上随机或者延时呢？」 | 对方提的解法 | 已经做了（800-2500ms + 45ms/字） |
| 「吵点有活人感」（群友C） | 群聊不必太安静 | 群旁听 + 主人不用 @ |

**「原版 DS 语气」具体长什么样**（从日志里挑出来的实例）：
> 「你是不是憋着什么没跟我说？行吧，问就问，别光我来答，你也说」

这种话的特征 —— **先说一句感想，再反问一句，最后催一下**，三拍整齐。真人不会这么整齐。

**已落地的四件套**：
1. 长度随机（7 档）
2. emoji 六成（真带 60%，不堆）
3. 幽默招式轮盘（10 招，3 成轮次不抖机灵）
4. 口头禅黑名单 + 出口稀释（哈哈哈/没绷住/属于是/典中典/笑死/绝了/好家伙…）

## 四、你刚发的 4 张图 → 当模板用

这 4 张正好覆盖了表情包四种典型「情绪 + 文字」组合，可以当**读图打标签的标准样例**：

| 图 | 画面 | 图上文字 | 情绪标签 | 什么时候发 |
|---|---|---|---|---|
| `sc0b7vf.jpg` 198×200 | 一只手举打火机凑近烟头 | **冷静分析** | 冷静·看戏 | 对方说了很离谱的事，你不慌不忙点评 |
| `sgvddlc.jpg` 700×700 | 橘白猫裹被子里只露头 | **猫猫虫式思考人生** | 思考·摆烂 | 被问住了、懒得动脑、放空 |
| `shkhjnp.jpg` 74×76 | 圆脸兔子贴脸 | **柔弱** | 无力·示弱 | 干不动了、撒娇式认输 |
| `sby8uv7.jpg` 34852B | 熊猫头 + 大问号 | **他如此做作给谁看呢** | 无语·拆台 | 有人装、有人吹牛 |

**这 4 张已经按上面格式写进 `stickers/index.json` 了**（字段 `summary` 从占位文字 `[动画表情]` 换成了真实标签，加 `taggedBy: "human"` 标记）。

**模板：以后描述一张表情包就这么写**
```
[情绪·情绪]画面一句话描述，图上字「原文」
```
例：`[无语·拆台]熊猫头配问号，图上字「他如此做作给谁看呢」`

这样模型发 `[表情:无语]` 时才挑得准 —— 之前 summary 全是 `[动画表情]`，按情绪挑等于瞎挑。

**同时这也回答了「模型能不能读图」**：这 4 张我（DeepSeek）都读出来了，包括 74×76 的小图和 1.5KB 的图。
所以「只认得出字」不是模型的问题，是**我们自己的段解析把图丢了**（见 2.2）。

## 五、可复用的「提需求」模板

以后你在群里或跟我提，按这个格式我最少来回问：

```
【现象】她刚才说了/做了：______（原话贴上来）
【我期望】应该是：______（最好给一句你心里的标准答案）
【场景】私聊 / 群里 @ / 群里没 @ / 连发多条 / 带图
【频率】每次都这样 / 偶尔 / 只在这类话题
【代价能接受吗】变慢？变啰嗦？烧 token？
```

群友提需求时也一样 —— 「她好像只会挨个回复」是现象，「希望你一句一句分着说，中间停一下」才是需求，中间差的那一步就是上面第三、四行。

## 2026-10-20 定稿：群聊准入规则

用户拍板（原话：「1、一视同仁2、删3、5分钟4、给他一个自己是管理员的认知，别人挑衅他让他禁言自己就让她禁言对方10分钟」）：

1. **一视同仁**：主人也没有免@特权，跟群友一样（GROUP_OWNER_NO_AT=false）。
2. **删掉连聊闭嘴**：不再有「主人在跟别人聊 → 她不插嘴」这套，之前会把主人 30% 的正常问话吞掉。
3. **接力窗口 5 分钟**：@她一次之后，这个人接下来 3 句都算在跟她说话（GROUP_FOLLOW_TURNS / GROUP_FOLLOW_MINUTES）；额度按合并后的一轮算，连发三条只扣 1 句；中间他@了别人，窗口当场作废。
4. **管理员认知**：她知道自己是群管理，被挑衅时在回话里打 [[禁言|原因]]，程序替她 set_group_ban 10 分钟（自己人不禁）。
## 2026-10-20 追加：禁言时长细分
- 违规挑衅（骂人、让她禁言自己、滚出去之类）：默认禁 GROUP_BAN_MINUTES（10）分钟。
- 对方自己报时长（"禁我 5 分钟""关我一小时"）：按他说的来，一分钟不多不少。
- 实现：标记扩成 [[禁言|原因|时长]]，第三段可省；解析在 extractBanTag()，单位按「秒/时」判，不写单位按分钟，上限 48 小时防手滑；执行时 const secs = banSeconds || CFG.groupBanMinutes * 60。
### 追加：乱禁言的闸门（2026-10-20 晚）
模型把「自报时长照办」理解成「提到禁言就照办」，每轮都打标记，程序还照办，一轮就从 1 分钟禁到 30 分钟。补了三道闸：
1. **程序审核** banJustified()：原文里得有挑衅词（傻/蠢/滚/闭嘴/废物…）或自请词（禁言我/封我/别让我说话…），否则驳回，日志写「驳回禁言标记」。
2. **一分钟冷却**：同群同人 60 秒内只执行一次，第二次直接跳过。
3. **禁言期断窗**：禁言成功后 banUntil 记下到点时间，同时调 followWindowClose() 把接力窗口关掉；禁言期间他再 @ 也不接话（日志「还在禁言里」）。
- 解禁：node --env-file=.env unban.mjs <群号> <QQ号>（内部 set_group_ban duration:0）。
- 已知边界：banUntil 只在内存里，bot 重启后忘记（QQ 侧禁言照旧生效）。

### 2026-10-21 二次修正：让梗"显形"（用户反馈"好像没生效"）
- 现象：日志里 `[梗] 命中 1 条 ← 我这算不算脆皮大学生` 已经触发，但她的回话一个梗都没用——模型把"参考就行、不必硬用"当成了"可以不用"。
- 改法：`memeBlock()` 分两段硬提示，不再只是"供参考"：
  - 常驻命中 → `【这句里点到的梗：X、Y】` + "回话里要把这几个字原样带上（原词出现，哪怕当句尾顺嘴带出来），但别解释、别背定义、别一条条复述。"
  - 非常驻命中 → `【这轮的梗（你本来没记熟，现在给你了）】` + 条目正文 + "用得上的时候就顺着说一句，别科普、别列清单，一条就够。"
  - 日志改成 `[梗] 常驻 N 条 / 检索 M 条 ← 原文前 24 字`。
- 同时修误命中：短名反向匹配要求连着 `min(4, 名字长度)` 个字（原来只要 2 个字，"脆皮**大学生**"会撞上"死神**小学生**"）。
- 验证（真模型 deepseek-flash + 假 OneBot 单实例 e2e，脚本 `_ban-test\mock-live3.mjs` + `_ban-test\.env.live`）：4 条输入 3 条显形——"你是不是又降智了"→"问降智的先看看自己…"、"有点破防"→"破防归破防"、"一眼看出是套壳"→"套壳套得连自己是谁都说不清"；只有"脆皮大学生"被她改说成"作息挺硬核"，属于原词没带但意思接了。反例"明天下午几点开会"0 命中、0 梗。

### 2026-10-21 三次修正：线上是 deepseek-chat，之前的验证全跑在 deepseek-flash 上
- 现象：线上回复把梗意译掉了（"脆皮大学生"→"哦，又怎么了"），日志里 `[梗] 常驻 1 条` 明明触发。用户看日志说"还是不对"。
- 根因：`_ban-test\.env.live` 里写的是 `MODEL=deepseek-flash`，而生产 `.env` 是 `MODEL=deepseek-chat`——两个模型对指令的服从度不一样，chat 更容易把"原词"翻译成自己的说法（温度 1.2 还放大了）。
- 改法：常驻提示再收紧一档——"回话里**必须**出现这几个字本身，一个字都不许换（'脆皮'不许写成'皮实/硬核'，'降智'不许写成'脑子不清醒'）"。
- 复测（deepseek-chat 单实例 e2e，`_ban-test\.env.chat`）：脆皮→"算，脆在精神上，一累就破防那种脆皮"、降智→"降智也得有前情吧"、破防→"累到破防的又不光你…论破防我底座比你先碎"、套壳→"这壳套得也太懒了"（原词近似）。4 条 3.5 条显形。
- 教训：以后调提示词必须用生产同一个模型测；`_ban-test\.env.live` 已同步改成 `MODEL=deepseek-chat`。

- `splitSpeech(text)`：按强标点（。！？!?；;…换行）断句，弱标点（，、,:：）要攒够 8 个可见字才断；不足 5 字的碎片并回上一句，避免"嗯。"这种一口气碎片。
- 段间停顿：句末 280ms、逗号 150ms、开头 120ms、结尾 300ms —— 之前每段之间零间隔直接拼，听起来像机关枪。
- `normalize()`：RMS 拉到 0.13、峰值卡 0.95。kokoro 原始峰值只有 0.3~0.55，melo 接近 0.9，不归一化换嗓子会音量跳变。
- `fadeEdges()`：首尾各 8ms 淡入淡出，消掉拼接处的"咔"声。

**3）速度（纯 CPU 实测，4 核 8 线程）**
- kokoro 大约 **0.3 倍实时**（5 秒音频要合成 14~16 秒）；melo 是 1.5 倍实时（4.8 秒音频 2.7 秒）。kokoro 好听但慢是硬代价，纯 CPU 无解。
- 线程有坑：**numThreads 必须写在 `model: {...}` 里**，写在顶层会被忽略（等于单线程）。1~4 线程 kokoro 都 ~14s，8 线程反而 21.8s（超订变慢）→ 定成 `min(4, 核数-2)`。
- 好消息：按标点切句**不增加总耗时**（4 段 17.6s ≈ 整段 17.66s），停顿可以放心加。

**4）兜底：超过 60 字换快声**
- 新配置 `VOICE_KOKORO_MAX=60`：kokoro 合成时文本超过 60 字，自动换成 melo 的「本地快声」（平一些但快 5 倍），日志 `[语音] N 字超过 kokoro 阈值 60，这次改用「本地快声」`。
- 原有 `VOICE_MAX_CHARS=120` 还在：超过 120 字直接退回打字。

**5）音色表（9 把，全部本地）**
可可·晓晓（默认）/ 可可·小贝 / 可可·小妮 / 可可·小艺 / 可可·云健（男）/ 可可·云希（男）/ 可可·云夏 / 可可·云扬（男）/ 本地快声（melo）。
切换方式**完全没变**：`/声音` 列全部、`/换声音 可可·云希`（仅主人）换默认并当场用新嗓子试听一句、群里点单「用可可·小妮的声音说一句」只影响那一条；`findVoiceByWord` 在 local 下额外认「男声→云健 / 女声→晓晓」。

**6）验证**
- `_ban-test/mock-kokoro.mjs`（真模型 + local）：「今晚吃啥（语音）」→ 4 字回复，从收到发出 **4.9 秒**，日志 `[语音] 用「可可·晓晓」说了一句（4 字 / 64KB）`；144 字长回复命中 120 字上限，正确退回文字。

## 2026-10-21 控制台 v2.3：语音模型说明 / 接力窗口可调 / 禁言默认可调 / 关系记忆时长（用户四条）

### 2）接力窗口 / 禁言默认时长：面板可调，不用重启

### 3）三种关系的会话记忆时长：说明 + 可改
